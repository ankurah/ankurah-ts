# Wire Format Interoperability

## Overview

ankurah-ts nodes must be able to sync with Rust ankurah nodes. This requires byte-level compatibility for the wire protocol (NodeMessage) and state encoding (Entity state buffers, events).

## Current Rust Serialization

| Data Type | Format | Used For |
|-----------|--------|----------|
| `NodeMessage` | bincode | Wire protocol between nodes |
| `EntityState.state` | bincode (BTreeMap<String, Vec<u8>>) | State buffers per backend |
| `Event.operations` | bincode (Vec<Operation>) | CRDT operations |
| `Clock` (Vec<EventId>) | bincode | Causal clock |
| `Attested<T>.attestations` | bincode | Cryptographic attestations |
| LWW backend state | bincode (BTreeMap<PropertyName, Value>) | LWW property storage |
| Yrs backend state | Yrs update encoding (v1/v2) | CRDT text state |
| SQLite storage | bincode for state/events, TEXT for IDs | Persistence |

## Bincode Compatibility Strategy

### The Challenge

Bincode is a Rust-specific binary format with no official TS implementation. We need to either:
1. Implement a bincode encoder/decoder in TypeScript
2. Switch to a language-neutral format for interop

### Recommended Approach: Hybrid

1. **Wire protocol**: Implement bincode encoding/decoding in TS for the specific types used in `NodeMessage`
2. **Local storage**: Use a TS-native format (e.g., msgpack or JSON) since local storage doesn't need cross-language interop
3. **Yrs/Yjs state**: Already interoperable - Yjs and Yrs use the same update encoding

### Bincode Reference Test Suite

**This is critical**: Add reference test infrastructure to `ankurah/proto` that generates known-good serialized bytes for every protocol type, enabling the TS port to validate its bincode implementation.

fn write_fixture<T: Serialize>(dir: &Path, name: &str, value: &T) {
    let bytes = bincode::serialize(value).unwrap();
    fs::write(dir.join(name), bytes).unwrap();

fn write_fixture_json<T: Serialize>(dir: &Path, name: &str, value: &T) {

## Bincode Encoding Details

Bincode uses a specific encoding that must be replicated exactly:

### Integers
- Little-endian by default
- Fixed-size (u8, u16, u32, u64, i8, i16, i32, i64)
- Varint encoding for lengths (with bincode v1 config)

### Strings
- Length-prefixed (u64 length, then UTF-8 bytes)

### Enums
- Variant index as u32, then variant data

### Structs
- Fields serialized in order, no field names

### Vec<T>
- Length as u64, then elements in order

### Option<T>
- 0u8 for None, 1u8 then value for Some

### BTreeMap<K, V>
- Length as u64, then key-value pairs in sorted order

### Implementation

A focused bincode implementation for ankurah's specific types (not a general-purpose library):

```typescript
// packages/proto/src/bincode.ts

export class BincodeReader {
    private view: DataView;
    private offset: number;

    constructor(buffer: ArrayBuffer) {
        this.view = new DataView(buffer);
        this.offset = 0;
    }

    readU8(): number { const v = this.view.getUint8(this.offset); this.offset += 1; return v; }
    readU16(): number { const v = this.view.getUint16(this.offset, true); this.offset += 2; return v; }
    readU32(): number { const v = this.view.getUint32(this.offset, true); this.offset += 4; return v; }
    readU64(): bigint { const v = this.view.getBigUint64(this.offset, true); this.offset += 8; return v; }
    readI16(): number { const v = this.view.getInt16(this.offset, true); this.offset += 2; return v; }
    readI32(): number { const v = this.view.getInt32(this.offset, true); this.offset += 4; return v; }
    readI64(): bigint { const v = this.view.getBigInt64(this.offset, true); this.offset += 8; return v; }
    readF64(): number { const v = this.view.getFloat64(this.offset, true); this.offset += 8; return v; }
    readBool(): boolean { return this.readU8() !== 0; }

    readBytes(): Uint8Array {
        const len = Number(this.readU64());
        const bytes = new Uint8Array(this.view.buffer, this.offset, len);
        this.offset += len;
        return bytes;
    }

    readString(): string {
        const bytes = this.readBytes();
        return new TextDecoder().decode(bytes);
    }

    readOption<T>(readInner: () => T): T | undefined {
        const tag = this.readU8();
        return tag === 0 ? undefined : readInner();
    }

    readVec<T>(readItem: () => T): T[] {
        const len = Number(this.readU64());
        const items: T[] = [];
        for (let i = 0; i < len; i++) items.push(readItem());
        return items;
    }
}

export class BincodeWriter {
    private buffer: number[] = [];

    writeU8(v: number) { this.buffer.push(v & 0xFF); }
    writeU16(v: number) { /* little-endian */ }
    writeU32(v: number) { /* little-endian */ }
    writeU64(v: bigint) { /* little-endian */ }
    // ... mirrors reader

    toBytes(): Uint8Array { return new Uint8Array(this.buffer); }
}
```

## Yrs/Yjs Interop

Yrs (Rust) and Yjs (JavaScript) use the same update encoding format. This means:

1. Yrs state buffers from Rust can be loaded directly by Yjs
2. Yjs updates from TS can be applied by Yrs
3. No translation layer needed for collaborative text data

```typescript
import * as Y from 'yjs';

// Load Yrs state buffer into Yjs document
const ydoc = new Y.Doc();
Y.applyUpdate(ydoc, yrsStateBuffer);  // Direct compatibility!

// Generate update for Rust node
const update = Y.encodeStateAsUpdate(ydoc);
// This can be sent to a Rust node and applied by Yrs directly
```

## LWW State Encoding

LWW backend state is a `BTreeMap<PropertyName, Value>` encoded with bincode. This needs a TS implementation:

```typescript
function decodeLWWState(buffer: Uint8Array): Map<string, Value> {
    const reader = new BincodeReader(buffer.buffer);
    const len = Number(reader.readU64());
    const map = new Map<string, Value>();
    for (let i = 0; i < len; i++) {
        const key = reader.readString();
        const value = readValue(reader);
        map.set(key, value);
    }
    return map;
}
```

## Alternative: JSON Wire Format

If bincode interop proves too complex or fragile, an alternative is to add a JSON wire format option to the Rust server:

```rust
// In the WebSocket server, negotiate format on connection:
// Client sends: { "format": "json" } or { "format": "bincode" }
// Server responds accordingly

// All NodeMessage types already derive serde::Serialize/Deserialize
let json_msg = serde_json::to_string(&node_message).unwrap();
```

This would be simpler to implement and debug, at the cost of larger payloads. For a mobile client, the payload size difference may be acceptable (most ankurah messages are small).

**Recommendation**: Start with JSON wire format for rapid development, add bincode for production optimization. The reference fixture approach works for both formats.

## Operation Encoding

CRDT operations within Events need special attention:

```rust
pub struct Operation {
    pub backend: String,      // "lww" or "yrs"
    pub data: Vec<u8>,        // Backend-specific operation bytes
}
```

- **LWW operations**: Simple key-value updates (bincode-encoded)
- **Yrs operations**: Yrs update encoding (wire-compatible with Yjs)

The TS port must decode operations by checking the `backend` field and routing to the appropriate decoder.
